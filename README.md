# for_dashboard — 금융 대시보드 98 (public)

Windows 98 레트로 감성의 **대시보드 런처(바탕화면)** 와 그 안에서 실행되는
대시보드들로 구성된 정적 사이트입니다. → <https://hahajongha.github.io/for_dashboard/>

- **메인 화면**: `index.html` — Win98 스타일 바탕화면. 아이콘을 더블클릭하면
  해당 대시보드가 창으로 열립니다 (시작 메뉴·작업표시줄·창 이동/크기조절 지원)
- **KOSPI 시그널 랩**: `dashboards/kospi_signal.html` — 아이디어별 신호·전략을 **번호 붙은 전략 묶음**으로 모은 검증·모니터링 대시보드
  - **1 BOP · 이격도**: Balance of Power(BOP) 매수 신호와 50일 이동평균 이격도 매도 신호가 KOSPI 변곡점을 잡는지 검증하는 백테스트
    (계산 엔진: `dashboards/kospi_signal_engine.js`)
  - **2 업종 2등주**: TIGER 반도체·헬스케어·2차전지테마 중 지난달 수익률 2등을 보유하는 전략 모니터 (계산: `dashboards/kospi_signal_tiger.js`)
  - 엑셀 읽기는 공용 `dashboards/kospi_xlsx_lite.js`
- **TAA 인컴 포트폴리오**: `investment_model/` — 미국 ETF 25종 월간 인컴/배당 포트폴리오 모델(Python)과 대시보드.
  데이터 갱신·모델 실행은 이 저장소의 GitHub Actions가 합니다 (아래 [TAA 인컴 포트폴리오](#taa-인컴-포트폴리오-investment_model) 참고)
- **데이터**: `data/kospi_signal.json` — private 저장소 `for_data`에 엑셀을 올리면
  GitHub Actions가 자동으로 생성·발행하는 KOSPI 일별 OHLC (원본 파일의 전체 기간).
  `data/kospi_tiger.json` — 같은 엑셀의 `TIGER` 시트에서 발행하는 ETF 4종 일별 수정 종가 (2 업종 2등주)

## 데이터 갱신 (엑셀 업로드 → 자동 반영)

```
[private] for_data                                     [public] for_dashboard (이 저장소)
data/kospi/*.xlsx ──push──▶ GitHub Actions ──▶ data/kospi_signal.json ──▶ KOSPI 시그널 랩
(벤더 원본, 비공개)          (파생 데이터 생성·발행)    (KOSPI 일별 OHLC 전체 기간 공개)
```

1. github.com → `hahajongha/for_data` → `data/kospi` 폴더 → **Add file → Upload files**
2. 벤더 엑셀(양식 그대로, `BOP` 시트 포함)을 끌어다 놓고 **Commit changes**
3. 약 2분 뒤 사이트에 반영됩니다 (for_data → Actions 탭에서 진행 상황 확인)

원본 데이터는 데이터벤더 제공으로 **비공개 저장소에만 존재**하며,
이 저장소에는 대시보드 표시에 필요한 값만 발행됩니다 — KOSPI 일별 시가·고가·저가·종가, TIGER ETF 4종 종가, 업종별 종가지수(업종명만) (원본의 다른 시트는 발행하지 않음).
자세한 규칙은 for_data 저장소의 README를 참고하세요.

## KOSPI 시그널 랩 구성

화면은 **전략 묶음 → 탭** 2단계입니다. 맨 위 번호 카드로 묶음을 고르고, 묶음 안에서 탭을 고릅니다
(탭이 하나뿐인 묶음은 탭 줄 없이 바로 화면). 번호는 아이디어를 추가한 순서이고, 새 아이디어는 다음 번호 묶음으로 하나씩 붙입니다
(아래 [새 전략 묶음 추가](#새-전략-묶음-추가)). 머리글의 설명·데이터 줄과 바닥글은 고른 묶음에 맞게 바뀌고,
엑셀 업로드·[데이터 · 계산 방법] 창·테마는 모든 묶음이 함께 씁니다. 묶음마다 마지막으로 본 탭을 기억합니다.

| 번호 | 묶음 | 탭 | 데이터 (엑셀 시트) | 조건 입력 |
|---|---|---|---|---|
| 1 | BOP · 이격도 | 차트·신호 · 성과·최적 조합 · 신호 검증 | `data/kospi_signal.json` (`BOP`) | 왼쪽 설정 패널 |
| 2 | 업종 2등주 | (한 화면) | `data/kospi_tiger.json` (`TIGER`) | 화면 안 [분석 조건] |
| 3 | 업종 추세 · 시장 폭 | 매매 신호 · 업종 순위·단계 · 시장 폭 · 규칙 검증 | `data/kospi_sector.json` (`SECTOR`) | 화면 안 [분석 조건]·[매매 규칙 설정]·차트 칩 |

- **주소**: `#chart`·`#perf`·`#check`·`#tiger`·`#trade`·`#sectors`·`#breadth`·`#rules`처럼 탭 id로 바로 열고, `#bop`·`#second`·`#trend`처럼 묶음 id로 열면 그 묶음에서 마지막으로 본 탭이 열립니다.
  `#data`는 [데이터 · 계산 방법] 창입니다.

### 1 BOP · 이격도

두 지표로 KOSPI 변곡점을 확인합니다.

- **매수(B)**: BOP(14일 평균)가 기준선(기본 −0.20, −0.20~−0.25 구간 검토) 아래로 내려서는 날
  — BOP = (종가 − 시가) / (고가 − 저가) (엑셀 `Bulls − Bears` 수식과 동일)
- **매도(S)**: 종가 / 50일 이동평균 × 100 (이격도)이 기준선(기본 120%, 120~130% 구간 검토) 이상으로 올라서는 날
- **B⁺(이중 확인)**: B 조건과 "이격도 ≤ 상한(기본 95%)"이 함께 처음 충족된 날
- 같은 신호는 **최소 간격**(기본 10거래일) 안에 다시 내지 않습니다 (1로 두면 모든 진입 — 이전 버전과 같은 신호)
- 왼쪽 **설정 패널**에서 기간, 기준선·평균 기간, 보유/대기 일수, B 최대 대기, 이중 확인 상한,
  세부 가정(최소 간격·체결 시점·비용·현금 수익률)을 입력하면 이 묶음의 세 탭에 모두 적용되고 이 브라우저에 저장됩니다.
  누적 성과는 **기준가 1000**으로 KOSPI Buy & Hold와 비교합니다.

| 탭 | 내용 |
|---|---|
| 차트·신호 | 현재 상태 판정 문장, KOSPI·BOP 평균·이격도 차트 위 **B / S / B⁺ 신호(ON·OFF)**, 전략 매매 표시(보유 구간 음영·체결점), 신호 내역(행을 누르면 그 날짜로 이동) |
| 성과·최적 조합 | 누적 성과(기준 1000)·낙폭, 전략 7종 성과표(평가 기준 선택·규칙 설명), **임계치 조합표**(칸을 누르면 그 기준선 적용), 연도별 수익률, 매매 내역, 과최적화 점검(IS → OOS) |
| 신호 검증 | B·B⁺·S 판정 문장, 신호 후 0~60일 평균 경로, 신호 후 수익률 vs 평상시(p-value·방향 판정), 기준선별 비교 |
| [데이터 · 계산 방법] 창 (공용) | 엑셀 업로드, 데이터 점검 결과, CSV 내보내기, 묶음별 계산식·가정·유의사항 |

- **차트 조작** (보기만 바뀌고 분석 기간은 그대로 — [이 구간으로 분석]을 누를 때만 기간이 바뀜)
  - 드래그: 구간 확대 · Shift+드래그 또는 차트 아래 미니맵 끌기: 이동(미니맵 양 끝은 폭 조절)
  - Ctrl(⌘)+휠·트랙패드 핀치·두 손가락 핀치: 확대/축소 · 더블클릭 또는 [전체 보기]: 처음 화면
  - 차트를 누른 뒤 ←/→ 날짜 이동(Shift는 10일), +/− 확대, 0 전체 · 터치 한 손가락: 값 확인
  - 성과 탭의 누적 성과 차트는 차트·신호 탭과 보기 범위가 연동됩니다(‘보기 연동’ 칩으로 끄기)

- **데이터 범위**: 기본 데이터(`data/kospi_signal.json`)는 원본 파일의 **전체 기간**(2000년~)을 포함합니다.
  공개 범위는 for_data 저장소 `scripts/build_kospi_signal_data.py`의 `PUBLIC_LOOKBACK_DAYS`로 조정합니다.

### 2 업종 2등주

한화투자증권 MP전략(2024.8) p.19~22의 **2등주 전략** 모니터입니다. 한 화면에 이번 달 보유 2등주·월중 성과·다음 달 잠정 2등주,
1등·2등·3등·1+2등주와 TIGER 200 누적 성과(일별)·낙폭·보유 업종 띠, 전략별 성과표, TIGER 200 대비 상회 업종 수 분포,
전월 → 이번 달 순위 전환표, 월별 순위표(CSV)가 있습니다. 화면 안 [분석 조건](기간·순위 기준 1/2/3/6개월·매매 비용)만 적용되고,
1번 묶음의 왼쪽 설정 패널은 보이지 않습니다.

- **데이터**: `data/kospi_tiger.json`은 원본 `TIGER` 시트(2019년~)의 TIGER 반도체(091230)·헬스케어(143860)·
  2차전지테마(305540)·TIGER 200(102110) 일별 수정 종가입니다. 월말 순위와 전략 성과는 브라우저가 계산합니다.
  매월 마지막 거래일 종가로 순위를 매겨 다음 달 한 달 보유하며(월말 종가 체결 가정), 통계는 끝난 달만 씁니다.

### 3 업종 추세 · 시장 폭

업종별 일별 종가지수로 **주도 업종과 시장 폭**을 봅니다 (마크 미너비니의 추세 템플릿·단계 분석을 업종 지수에 적용). 업종은 업종명으로만 표시합니다.

| 탭 | 내용 |
|---|---|
| 매매 신호 | 아래 **매매 규칙**을 지금 데이터에 적용한 결과 — 이번 달(또는 다음 달) 보유와 **할 일 표**(매수·유지·매도·현금으로, 목표 비중, 투자 금액을 넣으면 종목별 금액, 상태·이유), 달이 끝나기 전이면 **다음 신호 미리 보기**(최근 값 기준, 장중 저장이면 ‘장중 값’), ① 비중 — 월말 시장 폭 신호 기록(다음 달 KOSPI·결합 수익률), ② 업종 후보 — 2단계 + RS 70 이상 업종(없으면 가장 가까운 업종), 매매 규칙 설정 |
| 업종 순위·단계 | 기준일 판정 문장(2단계·4단계 업종 수, 가장 가까운 업종, 최근 5거래일 2단계 진입·이탈, RS 상위, 52주 고점에 가까운 업종), **단계 지도**(2·3·4·1단계 — 3단계는 200일선 위·아래로 나눔), **업종 순위표**(RS·1/3/6/12개월·추세 템플릿 1~8 칸·단계와 시작일·50/200일선·52주 고점/저점 대비, 머리글로 정렬, CSV), 고른 업종의 **상세 차트**(종가지수·50/150/200일선·RS 백분위·단계 띠) |
| 시장 폭 | 판정 문장, KOSPI와 업종 동일가중 지수 · 2단계/200일선 위/50일선 위 업종 비율 · 52주 신고가·신저가 업종 수 차트, 지금 시장 폭의 역사적 위치, **다이버전스 점검**(KOSPI 52주 신고가일의 2단계 업종 수 vs 그 전 1년 최대), **과거 비슷한 국면**(200일선 위 업종이 적었던 때 KOSPI 1·3·6·12개월 뒤 수익률), 월말 시장 폭 표(일별 CSV) |
| 규칙 검증 | 매매 규칙을 지금 데이터로 처음부터 다시 계산 — 판정 문장(설정과 다른 체결 시점 — 신호 당일 ↔ 다음 거래일 — 으로 계산한 비교 줄 포함), 규칙별 **누적 성과·낙폭 차트**(결합 규칙 보유 띠, 기간 1·3·5·10년·전체), **규칙별 성과표**(연복리·최대 낙폭·변동성·투자한 달·회전율, 비교 대상 대비 초과·Newey-West t값·p값·이긴 달·최근 2년 뺀 값), 월별 기록(월별 CSV) |

- **정의**: RS = 3·6·9·12개월 수익률 40/20/20/20 가중 점수(또는 3·6·12개월 단독)의 그날 업종 사이 백분위 ·
  추세 템플릿 1 P>150·200일선 · 2 150일선>200일선 · 3 200일선>21거래일 전 · 4 50일선>150·200일선 · 5 P>50일선 · 6 P≥1.3×52주 최저 · 7 P≥0.75×52주 최고 · 8 RS≥70 (종가 기준) ·
  단계 2 = 1~7 모두 충족, 4 = P<150·200일선 + 150일선<200일선 + 200일선 하락, 그 밖은 직전 확정 단계가 2면 3, 4면 1.
- **판정 기간**: 추세 템플릿·단계는 업종마다 252거래일(52주) 이력이 있어야 판정하고, 값이 빠진 날이 있으면 그날부터 252거래일 동안 ‘판정 전’입니다.
  시장 폭·역사적 위치·과거 비슷한 국면은 모든 업종을 판정할 수 있는 날부터 셉니다.
- **매매 규칙** (매달 마지막 거래일 종가로 신호 → 다음 달 마지막 거래일까지 보유):
  ① 비중 — 200일선 위 업종 비율이 기준(기본 50%) 이상이면 보유, 미만이면 현금 ·
  ② 업종 후보 — 2단계 + RS 백분위 70 이상 업종을 같은 비중으로 ·
  결합 — 비중 신호가 꺼지면 현금, 켜지면 업종 후보, 후보가 없으면 KOSPI(또는 현금).
  비교용으로 비중 신호만(KOSPI ↔ 현금), 업종 후보만(항상 투자, 후보가 없으면 업종 동일가중), RS 상위 5, 4단계 업종(참고), KOSPI 보유, 업종 동일가중을 함께 계산합니다.
  달이 끝나기 전에는 마지막으로 끝난 월말 신호가 이번 달 보유를 정하고(끝남 판단은 2 업종 2등주와 같은 규칙 — 엑셀 저장 시각·달력),
  최근 값 신호는 미리 보기로만 보입니다. 비용 = 목표 비중 변화 Σ|Δw| × 편도 비용(체결일에 차감, KOSPI·업종 동일가중 기준선은 비용 없음),
  현금 = 설정한 연 수익률의 월 복리. 체결일 종가가 빠진 업종은 그달 수익률에서 빼고 나머지 보유 종목의 평균을 그 비중에 적용합니다(모두 없으면 그달은 통계에서 뺌). 체결 시점은 신호 당일 월말 종가(기본) 또는 다음 거래일 종가(보유 구간이 하루씩 밀림 — 마지막 행이 장중 값이면 그 값으로 끝나는 달은 진행 중)를 고릅니다.
  통계는 끝난 달만 쓰며(비중 신호만·KOSPI 보유는 KOSPI 수익률이 있는 달만), 규칙마다 표본이 다르면 그 기간·개월 수를 따로 적습니다. 비교 대상 대비 값은 둘 다 수익률이 있는 달만 비교하고(그 수가 다르면 성과표에 표시),
  t값은 Newey-West(3개월) 표준오차, p값은 정규 근사 양측값이며, ‘최근 2년 빼면’은 마지막으로 끝난 달까지 24개월(건너뛴 달 포함)을 뺀 값, 비교한 달이 24개월 미만이면 판단 문구 대신 ‘표본 부족’(차이가 매달 같아 t값을 구할 수 없으면 ‘판단 불가’)으로 표시합니다.
  누적 성과 차트의 기준가 100은 보이는 구간에서 표시한 선 모두에 값이 있는 첫날입니다(KOSPI 데이터가 업종 데이터보다 늦게 시작하면 그 뒤 첫날 · 보이는 구간에 값이 없는 선은 빼고 안내).
  시작 뒤 값이 빠져 모든 업종을 판정할 수 없는 월말은 신호 없이 건너뛰고 그 개수와 구간을 화면에 알리며, 그런 월말 바로 뒤 신호의 할 일 표는 그 전 신호와 비교합니다(비용 계산과 같은 기준).
  배당을 뺀 가격지수 기준이고, 업종 지수는 같은 업종을 따르는 ETF로 실행한다고 가정합니다.
- **조건**: 기준일(과거 날짜의 상태도 볼 수 있음, ‘KOSPI 52주 신고가일’ 버튼), RS 기준, 차트 기간·로그·표시 선, 비슷한 국면 기준(200일선 위 업종 0~5개)을 화면 안에서 고르고 이 브라우저에 저장합니다(`ui.sc`).
  매매 규칙 설정(비중 기준 30~70%, RS 기준, 후보가 없을 때, 체결 시점, 편도 비용, 현금 수익률, 투자 금액)과 규칙 검증 차트 설정은 `ui.tr`에 저장하며 두 탭이 함께 씁니다.
- **데이터**: `data/kospi_sector.json`은 원본 `SECTOR` 시트(2000년~)의 업종별 일별 종가지수입니다. 지표는 모두 브라우저가 계산하고,
  KOSPI 비교에는 1번 묶음의 KOSPI 종가를 날짜에 맞춰 씁니다. 업로드한 SECTOR 시트는 크기가 커서 `kospiSignal.upload.sector.v1`에 따로 저장합니다.

### 공통

- **엑셀 업로드로 바로 분석**: 대시보드의 [엑셀 업로드]로 벤더 원본(`BOP` 시트 포함, `TIGER` 시트가 있으면 2 업종 2등주, `SECTOR` 시트가 있으면 3 업종 추세 · 시장 폭에도 반영)을 올리면
  발행을 기다리지 않고 그 파일로 바로 분석합니다. 파일은 **브라우저 안에서만** 처리되며
  어디에도 전송되지 않습니다 (그 브라우저에만 보관, "기본 데이터로 되돌리기"로 삭제).
  엑셀은 자체 해석기(`kospi_xlsx_lite.js`)로 읽어 외부 라이브러리를 받지 않습니다 (.xlsx · .xlsm, 예전 .xls는 .xlsx로 저장 후 업로드).
  외부에서 받는 것은 글꼴(IBM Plex Sans KR, Google Fonts)뿐이며, 받지 못하면 기본 글꼴로 표시됩니다.

### 새 전략 묶음 추가

기존 묶음의 계산 로직은 건드리지 않고, 새 아이디어를 다음 번호 묶음으로 붙입니다.

1. **계산**: `dashboards/kospi_signal_<이름>.js`에 DOM 없는 순수 함수로 만듭니다(Node에서 `require`로 검증 — `kospi_signal_tiger.js` 참고).
   `kospi_signal.html`의 `<script src>` 목록에 한 줄 추가합니다.
2. **묶음 등록**: `kospi_signal.html`의 `GROUPS`에 한 항목을 추가합니다 — `id`(주소용), `no`(다음 번호), `name`·`tag`(카드),
   `desc`(머리글 설명), `tabs`(`[탭 id, 이름]` 목록, 탭 id는 랩 전체에서 고유), `kospi`(1번 묶음의 KOSPI 계산 결과가 있어야 그리는지),
   `settings`(왼쪽 설정 패널을 쓰는지), `head`(머리글 데이터 줄·바닥글). 카드와 탭 버튼은 여기서 자동으로 만들어집니다.
3. **화면**: 탭마다 `<section role="tabpanel" id="p-<탭 id>" hidden>` 패널을 추가하고, `RENDER`에 그리기 함수를 등록합니다.
4. **저장**: 설정은 `kospiSignal.settings.v2`의 `ui` 아래 새 이름으로 저장합니다(다른 앱 키와 겹치지 않게 `kospiSignal.*`만 사용).
5. **데이터**: 새 시트가 필요하면 for_data에 빌드 스크립트와 워크플로 한 줄을 추가합니다(for_data README "새 대시보드 데이터 추가하기").
   업로드 경로(`handleFile`)에서도 그 시트를 읽게 합니다.
6. **문서**: 위 묶음 표와 이 README, [데이터 · 계산 방법] 창에 묶음 구획을 추가합니다.

## TAA 인컴 포트폴리오 (`investment_model/`)

Claude Project에서 개발한 TAA Income Quant PM System v1.0(Model v3.0)을 옮긴 모듈입니다.
모델·방법론·운용 규칙은 **`investment_model/CLAUDE.md`**, 사용 설명은 `investment_model/README.md`,
상세 인수인계는 `investment_model/docs/HANDOVER.md`에 있습니다.

- **화면**: `investment_model/output/taa_pm_dashboard_v1.0_latest.html` (바탕화면 "TAA 인컴 포트폴리오").
  결과 JSON이 HTML에 내장되어 있어 서버 없이 표시되고, 실보유 비교·주문 계산·CSV 내보내기는 브라우저 안에서만 동작합니다.
  **실보유 입력**(수량·평균매입단가·현금 → 평가금액·손익·비중 자동 계산)과 **내 포트폴리오 기록**(원금 투입·월말 평가금액·수익률)은 그 브라우저의 localStorage(`taaPm.holdings.v1`, `taaPm.ledger.v1`)에만 저장되고 저장소로 올라가지 않습니다 — 백업·다른 기기는 [CSV 내보내기]/[CSV 불러오기], [백업 내보내기](JSON)를 쓰세요.
- **데이터 갱신 (수동)**: 화면 1단계 **[Update Data ↗]** → GitHub Actions *Update investment data* → **Run workflow**
  - `data_only`: yfinance·FRED·ALFRED 데이터만 갱신 / `model_run`: 데이터 갱신 + 모델 실행 (`as_of` 비우면 자동 인식)
  - 데이터 갱신마다 `investment_model/output/latest_prices.json`(유니버스 최신 종가)도 갱신 → 실보유 표의 평가금액을 월 중간에도 최신 종가로 볼 수 있습니다(목표·주문 계산은 모델 기준일 종가 그대로).
- **자동 실행**: 매월 1~5일 22:17 UTC, 기준일 = 직전 월 마지막 NYSE 거래일. 이미 기록된 월은 건너뜁니다.
- **안전장치**: 임시 복사본에서 다운로드 → 데이터 가드(이력 잘림·티커 누락·관측치 소실·빈티지 누락 등) →
  패키지 검증 → 모델 실행이 **모두 통과할 때만** `investment_model/data·history·output`을 교체합니다.
  실패하면 기존 데이터는 그대로이고 `investment_model/output/status.json`에 실패 사유만 기록됩니다.
- **워크플로**: `.github/workflows/update-investment-data.yml`(수동), `investment-model-monthly.yml`(예약),
  `_investment-model-pipeline.yml`(공통), `investment-model-tests.yml`(골든·주문엔진 회귀 테스트)
- **KOSPI 데이터와의 관계**: TAA 워크플로는 `investment_model/` 아래만 커밋합니다. `data/kospi_signal.json`은 계속 for_data 저장소만 씁니다.

## 새 대시보드 추가하기

1. `dashboards/` 폴더에 새 HTML 파일을 만듭니다 (예: `dashboards/fx.html`).
   데이터는 `../data/...` 상대 경로로 읽습니다.
2. `index.html`의 `APPS` 배열에 항목을 하나 추가합니다:

```js
{ id: "fx", name: "환율 대시보드", icon: "chart", type: "iframe",
  url: "dashboards/fx.html", desktop: true, startmenu: true, w: 1200, h: 760 },
```

바탕화면 아이콘과 시작 메뉴에 자동으로 등록됩니다.
(아이콘은 `ICONS`에 정의된 픽셀 SVG 키를 사용하며, 새 아이콘을 추가해도 됩니다.)
원본 엑셀은 for_data 저장소의 `data/<대시보드>/` 폴더에 두고 빌드 스크립트를 추가합니다 (for_data README 참고).
